# ADR-0015: SMRITI Installation Bootstrap Framework & Pure Authentication Isolation

## Status

Accepted (2026-07-29)

## Context

Previously, initialization tasks such as legacy default super administrator password reconciliation were executed lazily during runtime authentication calls (`AuthService.login`). This introduced side effects into the authentication path, mutating user account states during login requests and complicating security audits, diagnostics, and multi-instance concurrency.

## Decision

1. **Separation of Responsibilities**:
   - All initialization, seeding, migration, reconciliation, and upgrade tasks execute exclusively through the dedicated **Installation Bootstrap Service** (`BootstrapService`) at application startup.
   - Runtime business services, including the **Authentication Service**, operate strictly read-only with respect to account initialization and shall never modify user credentials or account states as a side effect of authentication.

2. **State Tracking**:
   - Bootstrap progress and metadata are tracked in `system_bootstrap_states` containing `task_name`, `status`, `started_at`, `completed_at`, `duration_ms`, `bootstrap_version`, `execution_count`, and `error_message`.

3. **Concurrency & Environment Isolation**:
   - Startup execution is guarded by PostgreSQL advisory locking (`pg_try_advisory_lock(891230491)`).
   - Development convenience credentials and password reconciliation execute only in `Development` and `Demo` environment profiles and are strictly disabled in `QA`, `Staging`, and `Production`.

4. **System Super Administrator Standard (SSA-001)**:
   - The built-in `super` account is the platform owner with full administrative capabilities through the authorization framework. It does not bypass authentication or security controls. All privileged actions must be authenticated, authorized, logged, and auditable.

## Consequences

### Positive
- Authentication path (`/api/v1/auth/login`) is 100% deterministic, side-effect free, and read-only.
- Installation bootstrap is idempotent, versioned, and safe across multi-container restarts.
- Full auditability via `system_bootstrap_states` and operational summary logs.
- Clear boundary between infrastructure bootstrap and business onboarding setup wizard.

### Trade-offs
- Small addition of startup execution overhead (tracked in `duration_ms`).
- Requirement for PostgreSQL table `system_bootstrap_states`.
