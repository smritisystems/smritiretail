# SMRITI Design Language Guide

**Status:** DRAFT GUIDE — v1.0 (2026-08-04)

## 1. Purpose

The SMRITI Design Language Guide defines the principles that shape the visual and interaction language of the SMRITI Design System (SDS).

## 2. Color Philosophy

- Use functional color first: success, warning, error, info, neutral.
- Reserve bold brand color for primary actions and emphasis.
- Prefer semantic palettes over decorative color accents.
- Ensure every palette passes WCAG contrast thresholds.

## 3. Typography Philosophy

- Use a single primary text family for readability and consistency.
- Use a monospace or tabular variant for numeric, currency, and code-like data.
- Limit headline hierarchy to three levels within a workspace.
- Preserve vertical rhythm with tokenized spacing.

## 4. Icon Rules

- Use iconography to clarify action and status—not to decorate.
- Prefer square, geometric icon shapes for enterprise clarity.
- Supply icon labels for all non-obvious actions.
- Keep icon size consistent across shared toolbars and buttons.

## 5. Illustration Rules

- Use illustrations sparingly for empty states, onboarding, and error messaging.
- Illustrations must be semantic, purpose-driven, and brand-aligned.
- Avoid playful or decorative illustration styles in core enterprise workflows.

## 6. Motion Philosophy

- Motion is meaning, not ornament.
- Use motion to indicate transition, hierarchy, error recovery, and confirmation.
- Keep motion duration consistent and moderate.
- Respect reduced-motion accessibility preferences.

## 7. Voice & Tone

- Keep messaging direct, concise, and helpful.
- Use action-oriented labels rather than abstract nouns.
- Prefer active verbs and plain language for prompts and notifications.
