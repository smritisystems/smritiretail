# ADR-025: Evidence & Fact Model Standard (EFMS-001)

**Status:** FROZEN — Level 1 Platform Architecture Standard v1.0 (2026-08-07)  
**Standard:** EFMS-001 through EFMS-006  
**Parent:** ADR-023 (Engine Constitution) & ADR-024 (Pack Standard)  
**Author:** Jawahar Ramkripal Mallah (Chief Systems Architect & Creator)  

---

## 1. Executive Summary

ADR-025 formalizes the **Evidence & Fact Model Standard (EFMS-001)**. It establishes an immutable schema for all diagnostic findings, facts, and evidence records produced by any Domain Pack in SMRITI Developer Operating System (SDOS). Freezing the Evidence Model ensures that report generators, snapshot stores, diff engines, and Developer Studio UI views remain 100% plug-and-play across all future releases.

---

## 2. Immutable EvidenceRecord Schema (EFMS-001)

All evidence items generated by any collector or rule MUST adhere strictly to the immutable TypeScript contract:

```typescript
export type SeverityLevel = "CRITICAL" | "HIGH" | "MEDIUM" | "LOW";

export type ConfidenceLevel = "VERIFIED" | "STATIC" | "DYNAMIC" | "INFERRED";

export type SourceType = "REGISTRY" | "AST" | "DOM" | "API" | "DATABASE";

export interface EvidenceRecord {
  id: string;                      // Unique evidence identifier (e.g. "EV-NAV-001")
  domain: string;                  // Target domain ("Navigation", "Security", "Runtime", etc.)
  severity: SeverityLevel;         // Rule severity level
  confidence: ConfidenceLevel;     // Finding confidence classification
  sourceType: SourceType;          // Extraction mechanism
  targetId: string;                // Affected entity symbol or menu ID
  file: string;                    // Relative source file locus
  line?: number;                   // Precise source line number
  message: string;                 // Concise failure description
  recommendation: string;          // Developer resolution guidance
  suggestedFixId?: string;         // Optional reference to deterministic fix handler
  timestamp: string;               // ISO-8601 timestamp
}
```

---

## 3. Confidence Classification Levels (EFMS-002)

Every finding MUST declare its extraction confidence using standardized platform categories:

| Confidence Level | Definition & Criteria | Certainty |
| --- | --- | :---: |
| **`VERIFIED`** | Extracted directly from Level 1 UPR Registries (`SPK.navigation`, `SPK.security`, `SPK.forms`). | **100%** |
| **`STATIC`** | Extracted via static source code analysis or AST parser. | **95%** |
| **`DYNAMIC`** | Extracted via live browser DOM or runtime singleton state inspection. | **85%** |
| **`INFERRED`** | Extracted via relationship graph topology heuristics or indirect coupling analysis. | **70%** |

---

## 4. Source Extraction Types (EFMS-003)

Evidence sources are classified into five explicit categories:

1. **`REGISTRY`:** Declarative UPR metadata registry facade (`SPK`).
2. **`AST`:** TypeScript / Python static AST file parser.
3. **`DOM`:** Live browser DOM runtime inspector.
4. **`API`:** Service endpoint registry and REST route inspector.
5. **`DATABASE`:** Entity definition framework and PostgreSQL schema inspector.
