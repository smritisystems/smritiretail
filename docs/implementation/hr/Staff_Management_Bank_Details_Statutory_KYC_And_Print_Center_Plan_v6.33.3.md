# Implementation Plan: Staff Management Bank Details, Statutory KYC & Print Center Architecture (v6.33.3)

## 1. Objective
Establish complete end-to-end statutory compliance, salary remittance banking architecture, and physical/digital printable artifact infrastructure across the SMRITI Retail OS Staff Management ecosystem. Provide statutory A4 Staff Registration & Remittance Forms (both filled with verified data and blank for physical onboarding) and CR-80 physical staff ID cards with scannable retail POS SVG barcodes and Blood Group medical indicators.

## 2. Business Motivation
Retail organizations operating in India must comply with statutory labor welfare and financial governance mandates:
1. **Payment of Wages Act & Digital Salary Remittance:** Requires structured bank account details (Bank Name, Account Number, IFSC, Branch, Account Type, Beneficiary Name, Remittance Mode) for direct credit, eliminating cash/cheque ambiguities.
2. **Statutory KYC Compliance:** Mandates recording of PAN (Income Tax Act), Aadhaar UID (PMLA/UIDAI verification), EPFO UAN (Employees' Provident Fund), ESIC Insurance IP (Employees' State Insurance), and emergency contact relations.
3. **Physical Store Operations & POS Attribution:** Frontline store associates require physical CR-80 badges containing deterministic 1D barcodes scannable by Honeywell/Zebra retail scanners at POS terminals (`ProPosBillingTerm.tsx`) for cashier login and commission attribution.
4. **Emergency Health Safety:** Blood group badges (`BG: B+`) on physical badges ensure immediate first-responder intervention during store accidents or warehouse emergencies.
5. **Physical Onboarding Workflow:** HR coordinators require official blank A4 registration forms with structured lines for on-site walk-in employee data collection prior to ERP entry.

## 3. Scope
- **Backend Schemas (`backend/app/schemas/user.py`):** Expansion of `PaymentDetails` with 14 structured fields for banking remittance and statutory KYC.
- **Backend API & Deserialization (`backend/app/api/v1/staff.py`):** Fix JSON string deserialization defect in `_merge_staff_profile`, initialize `profile_was_new = False` to prevent `UnboundLocalError`, and map `payment_json` updates.
- **Frontend Types (`src/types.ts`):** Synchronization of `User.payment` interface with backend contract.
- **Staff 360 Workspace (`src/components/staff/StaffMasterWs.tsx`):**
  - Addition of dedicated "Bank & KYC" tab.
  - Interactive Reveal / Mask toggle buttons for Account Number and Aadhaar UID.
  - 3-subtab editor (`General Info`, `Bank Remittance`, `Statutory KYC`) in `isEditing` mode.
  - Patching `PATCH /staff/directory/{user_id}/profile` with complete payment structure.
- **Print Center (`src/components/staff/StaffPrintModal.tsx`):**
  - 5-Section Statutory A4 Registration & Remittance Form supporting both "With Data" and "Without Data (Blank)" modes.
  - CR-80 Physical ID Card (Front & Back) with company logo, staff photo, employee ID, blood group pill badge, and SVG 1D barcode.
- **Testing & Verification:**
  - Automated Vitest test suite (`src/tests/staffBankDetailsAndPrint.test.ts`).
  - Headless Playwright automated browser verification (`scripts/test_headless_staff_print_and_bank.py`).

## 4. Current State
- Prior to this implementation, employee bank details were either stored as an unstructured single-line string (`payment.bankDetails`) or omitted entirely.
- Statutory KYC credentials (PAN, Aadhaar, EPFO UAN, ESIC IP, Blood Group, Father/Spouse Name) were absent from database models and schemas.
- In `backend/app/api/v1/staff.py`, `_merge_staff_profile` suffered from raw string clobbering where JSON strings from `StaffProfile` replaced dictionary structures generated by `to_staff_response`.
- Staff print center lacked blood group indicators on ID badges and lacked scannable barcodes for POS scanners.
- No printable blank onboarding form was available for physical walk-in staff registration.

## 5. Gap Analysis
| Domain / Component | Defect / Limitation | Required Architecture |
|---|---|---|
| Schemas (`user.py`) | Missing bank details & KYC fields | Explicit Pydantic models for bank & statutory KYC |
| API (`staff.py`) | `json.loads` omitted on serialized columns; `UnboundLocalError` on `profile_was_new` | Safe JSON parsing & proper variable scoping |
| Types (`types.ts`) | `User.payment` restricted to 3 legacy fields | 14 structured banking and KYC fields |
| UI (`StaffMasterWs.tsx`) | No dedicated Bank tab; no masking; flat edit form | Dedicated "Bank & KYC" tab, mask toggles, 3-subtab editor |
| Print (`StaffPrintModal.tsx`) | Missing Blood Group; missing scannable barcode; missing blank form | CR-80 badge with barcode + Blood Group; 5-section A4 form with blank mode |

## 6. Architecture Impact
1. **Zero Database Migration Required:** `StaffProfile.payment_json` is an authoritative `TEXT` column storing serialized JSON in PostgreSQL. Expanding the Pydantic schema preserves full schema backwards compatibility.
2. **Multi-Store Isolation:** All profile and payment modifications remain strictly scoped to `tenant.company_id` and authorized operator roles (`SYSADMIN`, `MANAGER`).
3. **Audit History Trail:** Every mutation to staff payment details records before/after state snapshots into `StaffProfileHistory` table.
4. **Clean Decoupling:** POS counter terminals read `employeeCode` from scanned barcode without requiring direct access to sensitive bank account details.

## 11. Risks
- **Sensitive Data Exposure:** Unmasked bank account or Aadhaar numbers in open workspace.
  - *Mitigation:* Default masked display (`•••• •••• 1234`) with explicit toggle buttons; print center restricted to manager/HR view.
- **Barcode Scannability:** Low contrast or non-standard aspect ratios causing retail POS scanner misreads.
  - *Mitigation:* Deterministic SVG high-contrast 1D barcode with human-readable text fallbacks.

## 12. Rollback Strategy
Git revert commit cleanly restores previous file states. No database schema alterations or migrations need reversal as `payment_json` column stores unstructured JSON text.
