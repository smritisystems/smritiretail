## Documentation conventions

- Use the home page as the primary entry point.
- Use architecture docs for system intent and boundaries.
- Use walkthroughs for release history and implementation rationale.
- Use troubleshooting docs for production support and incident handling.

## Suggested future cleanup

- Keep one canonical home page and one canonical architecture overview.
- Mark superseded or legacy documents as reference only.
- Link walkthroughs back to the actual module docs instead of duplicating them.
